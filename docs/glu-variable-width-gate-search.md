# Variable-width gate search — component validation

Source `examples/isolated_glu/variable_gate_search.py`, tests `tests/test_variable_gate_search.py`. This is a pure numerical candidate component; no actual registered public observations were loaded and no teacher/model forward or oracle queries were performed. Small literal numerical/RNG fixtures are explicitly distinguished from the still-unapproved six-job development run. Private gate CLOSED.

## Contract and source correspondence

`search_job(GateJob, initial_rng, rescue_rng, sink)` receives only the already validated opaque immutable job and two distinct injected PCG64 streams. No file paths, case/channel/width metadata, teacher factors, callbacks, references or new seeds are supplied. The future controller must validate the preregistered per-job seed domains before calling it. This component validates distinct PCG64 objects/states, not the external origin of those states.

Initial search adapts the frozen `glu32.directions` Adam geometry to n/r:256 raw normal starts, normalization,1600 Adam steps (moments .9/.999, learning rate .02, denominator1e-8), then12 calls to the frozen tangent-refinement steps. It recomputes original-basis projection losses for merge rather than trusting search/refiner success flags. The target r/2 remains a generic-family hypothesis.

For1..target-1 candidates, at most4 rescue rounds use frozen `residual_subspace`, two least tangent components, fixed256 normalized mixtures and two eigenvectors per mixture, then24 refinement steps. The former internal seed20261025 is replaced with the injected rescue stream. Merge uses loss<=1e-8 and strict absolute cosine<.9995, including sign duplicates, sorted-loss ordering and no target truncation. Zero, exact target, overshoot, unexpected component geometry and exhausted rounds are explicit outcomes. Nonfinite arithmetic and sink errors propagate as operational failures to the future controller.

Numerical correspondence is algorithmic, not a bit-parity claim. Post-refinement losses are recomputed with packed, batched projection and np.sum rather than reusing the frozen refiner's per-row float(r@r). Merge cosine calculation uses a batched matrix-vector product. Rescue chunk normalization batches eight coefficient rows rather than a single flattened norm. Summation/BLAS partition may change last bits near fixed thresholds; thresholds themselves are unchanged. Chunk-local losses and final aggregate losses can likewise differ at roundoff scale; authoritative merge decisions use the aggregate stored loss arrays. Any audit must compare these independently with explicit numerical tolerance, not assume exact last-bit equality.

## Trace and partial-failure contract

The sink receives immutable, finite native FP64 array snapshots. It records ASCII JSON PCG64 states padded to512 entries plus exact length before/after, raw and normalized starts, optimized pre-refinement inputs, refined outputs/losses, every merge's order/decision/maxcosine/nearest index, rescue input geometry/residual/tangent singular values, raw/normalized mixtures and all eigenvalues/eigenvectors/chosen indices. Final directions/losses/cosines and explicit count are persisted; empty outputs are padded with count0. A count match is named candidate_target, never certified recovery.

Independent review reproduced S1: a failure in refiner2 lost pre-refinement inputs and output1, and a later eigen failure lost completed mixture evidence. Both were fixed after targeted RED tests. Before refinement, the whole relevant input stage is saved. Fixed8-row refinement chunks emit intent and completed output/count/attempted/complete/index fields. On an ordinary exception, valid completed outputs in the current chunk are flushed, and the original exception is re-raised even if that flush also fails (with an explanatory note).

Rescue uses32 eight-mixture chunks. Intent precedes draws; raw/normalized inputs precede eigensolves. Completed eigen outputs and starts are written per chunk, with the same partial-flush semantics. The complete aggregate archives remain for audit. RNG draws retain their sequential call order, but numerical reduction need not be bit-identical to the old implementation.

An external kill, KeyboardInterrupt or simultaneous sink failure can leave the current chunk uncommitted. Up to8 completed computations in that chunk remain UNKNOWN; never infer completion from requested/attempted counters or regenerate/retry them. Inputs/intent and earlier committed chunks remain evidence. Ordinary-exception partial flush is best effort and cannot promise persistence after disk failure. The future outer controller must retain the global consumed marker, partial case statuses and resource receipts and must not label the attempt completed.
