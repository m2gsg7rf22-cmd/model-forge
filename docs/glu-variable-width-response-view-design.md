# Variable-width chosen-input/full-response observation contract

Status: DRAFT DESIGN ONLY. Independent design review pending. Implementation may follow design approval; no actual transcript access, RNG, fitting, query, teacher generation, or new experiment follows from this draft. Private final-model gate CLOSED.

## Decision and scientific purpose

The [independently audited six-case gate development](glu-variable-width-gate-outcome.md) reached only1/6hypothesized candidate counts. Five cases exhausted four rescue rounds; job00 gained12candidates, job01 gained1, and the other three deficient jobs gained none. Those are fixed-cutoff descriptive outcomes, not evidence of exact gate counts, a causal precision effect or a reason to loosen cutoffs. Preserve every result and consumed marker.

Choose a distinct observation contract for later full-map reconstruction research: retain the actual chosen continuous input vectors and observed full-vector responses from the owned paired-row acquisition. Hessian subspace search discards the association of each response with its chosen input. This contract makes that association available without original factors, analytic derivatives, reference rank labels or a teacher callback. It does not itself supply a new solver or prove that the finite observations identify the function.

Alternatives considered: adding starts or relaxing loss would adapt to consumed counts and still not establish full-map fidelity; a new algebraic rank-one solver remains a separate conditioning/research problem; restricting work to job04 would omit the difficult cases. All six cases remain mandatory. Earlier fixed-gate forward polish and gate-step failures in docs/glu-fp32-guarded-forward-convergence.md and docs/glu-fp32-guarded-gate-step.md remain failures; this contract does not rerun their fits or evaluations. A later joint full-map solver would need a distinct hypothesis and complete prospectively reviewed protocol, not merely those fixed-gate updates again.

## Adapter API and disclosure limits

Implement a separate `variable_response_view.py`, with no modifications to old signed sources. A parent provenance validator checks exact public pins and all408whitelisted file hashes/headers/finite contents in bounded streaming passes before returning any optimizer-readable data. It must not call generic truth-store inventory or recursive listing. Reject symlinks/aliased ancestry, unknown NPZ members, object/non-native dtype, nonfinite values, wrong dimensions/size, missing files, changed commitments and inconsistent counters. Pin dependencies and include meaningful mutation controls.

Expose opaque job00..job05 and immutable bytes-backed `ResponseBatch(inputs,responses)` arrays. A job reports only dimension32/output32 and fixed34batch count. Its iterator has the registered step/probe order; each batch contains2112rows. No physical path, teacher seed, channel hint, true width, context/reference data or callable target enters a numerical solver. Keep original IDs/channel/filenames/hashes and all source lineage in a separate parent adapter report. This is an API/dataflow separation, not OS isolation or statistically hidden channel/width: responses themselves may reveal properties, and identifiers can be linked to the public report. A solver must not be allowed arbitrary path or parent metadata arguments.

The validator retains at most one input/response pair while checking the whitelist, and stores only bounded descriptors/counters between pairs. A consumer may retain delivered immutable arrays; this is outside the adapter working-set guarantee and must be covered by the future controller TREE budget. Never materialize or cache all408arrays in the validator.

Use zero-copy SOURCE STORAGE: do not duplicate the220MBtranscript on disk. Immutable returned arrays are new in-memory copies, not memory sharing with mutable source files. Validate a complete pair and rehash against the precommitted descriptors on each yield; reject mutation before delivery. At completion, rehash all408whitelisted files and pinned public metadata without loading arrays; compare against the same frozen descriptors. Count filesystem reads and bytes separately for initial validation, per-yield delivery and completion hash revalidation. Delivered row/batch counters advance only after a complete pair has validated; no descriptor/hash read is counted as delivered data. A fully consumed job requires all34batches delivered in order; a partial/failed iteration is reported explicitly, with no inferred completion. Do not promise protection against a malicious concurrent writer or a continuous OS memory cap. Document how a failed/partial iteration is represented without inferring that all batches were delivered.

The adapter does not silently attach saved gate candidates or rank/2. If a later solver needs them as initialization, a distinct jointly reviewed input contract must bind both sources and explicitly distinguish hypothesized width from truth. This keeps the adapter useful for testing a full-response method without embedding success assumptions from count search.
