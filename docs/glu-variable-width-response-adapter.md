# Variable-width response adapter: fixture stage

This component implements the independently approved [observation design](glu-variable-width-response-view-design.md). It has not opened the original query transcripts. Component review, a complete distinct read-only protocol/controller/inventory and actual resource gates are required before any registered transcript access. No solver, new teacher/query, fitting, private asset or consumed heldout is involved. The private final-model gate remains CLOSED.

`examples/isolated_glu/variable_response_manifest.py:load_manifest(repository)` reads exactly four pinned PUBLIC metadata documents: the paired-v1 outcome audit, its artifact commitments, collection receipt and query-progress receipt. It checks native counters, source lineage, final batch and receipt hashes, then extracts exactly 204 input/response pairs (408 archives) from fixed absolute commitment keys. It never opens or enumerates the truth directory. The default profile is six cases, two steps, 17 probes, 2,112 rows per pair, input/output dimension32. Old archive placement is not permission to read adjacent context/factors/reference/seed/evaluator files. Public metadata pins are fixed in source; a fixture-only private seam permits tiny literal profiles and metadata.

`variable_response_view.py:open_view(root, manifest)` accepts only the fixed registered profile and fixed public digests. It recompiles the manifest from pinned public metadata to reject forged descriptors, then validates every allowed archive before exposing any jobs. Each encoded NPZ is capped at544,768 bytes, stored ZIP with exactly one field, NPY header at most4,096 bytes and exact native finite float64 shape. Header shape/dtype and payload length are checked before array construction. Symlinks, aliased paths and multiple-link files are rejected. The public commitment cap is2MiB; other metadata and the report cap are128KiB. No generic truth-store inventory is called.

The parent owns `ResponseView`, its provenance and separate counters. A future numerical learner receives only frozen opaque `ResponseJob(job_id,n,outputs,batch_count,batches)` and immutable bytes-backed `ResponseBatch(inputs,responses)`. A canonical single-use iterator revalidates each complete pair before delivery. Jobs must be consumed in order. Partial iteration is reported as partial; a fully delivered job has34batches. Errors terminally block further delivery, with no restart or retry. Closing an iterator early does not imply completion. An initial validation failure raises `ViewValidationError` with a bounded partial receipt; delivered rows remain zero.

Validation retains one pair at most and no cached scientific arrays. A helper returns each immutable delivery before the generator suspends, so the idle generator does not keep its previous pair alive. A consumer may retain arrays; that memory remains subject to the future controller TREE budget. This is synchronous API separation, not OS isolation, an adversarial writer guarantee or statistically blinded precision/width. Physical FP32 responses stored as float64 remain FP32-computed observations.

`finish()` requires every batch delivered, then rehashes all408whitelisted files and public metadata without decoding arrays. Validation, delivery and completion each count attempted/completed archive reads and bytes separately, plus metadata reads. Delivery separately counts pairs, rows and raw payload bytes only after both arrays validate. A failed filesystem read can make bytes a lower bound, explicitly recorded. The report is returned as an independent JSON copy; consumer edits cannot corrupt counters.

35 NEW literal fixture tests passed in0.22s; strict mypy passed both modules and Ruff passed both plus their test file. Initial missing-module/view failures were observed before implementation. Two extra regressions caught idle-generator retention and loss of a partial initial-validation receipt, then passed after fixes. An early fixture test accidentally counted its own four digest reads as compiler reads; setup was moved before the observation guard, retaining exactly-four compiler reads. A subsequent PUBLIC-metadata-only production check found a compatibility bug: the prior audit uses relative `collection/...` keys in `metadata_sha256`, while `artifact_sha256` uses absolute archive keys. The initial literal fixture had incorrectly represented both maps as absolute. The fixture was corrected first, its compiler test failed as expected, then the compiler was fixed; all35tests passed. The corrected production metadata check produced204pairs/408descriptors/430848rows without any transcript opening. This was metadata compatibility evidence only, not actual raw schema/value verification. The independent review preserved its pre-fix literal probes and challenged the relative-key correction separately. No old numerical experiment, successful package build or broad completed suite was repeated. There is no new cross-platform/native GUI claim.

The tiny fixtures challenge all-before-exposure failure, public pin/schema/counter changes, duplicate JSON keys, immutable arrays, canonical job order, exhausted/partial iterators, late delivery and completion mutations, unknown ZIP members/duplicates, malicious NPY shape, nonnative schema, nonfinite values, caps, links, forged descriptors and forbidden directory/read sentinels. They do not validate actual transcript values or resource measurements.
