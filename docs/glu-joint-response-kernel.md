# Joint response numeric kernel: implementation boundary

This pure NumPy component implements the approved [development design](glu-joint-response-development-design.md). It is not an observation reader, executable experiment protocol or reconstruction result. No actual transcript, registered random stream, target query or teacher is used by its literal tests. The final private-model gate remains CLOSED.

`joint_response_kernel.Parameters` owns immutable bytes-backed native finite FP64 matrices G/U/D, with input/output dimensions at most32 and hypothesized width at most96. `predict` streams candidate forward arithmetic in4096row chunks. `loss_gradient` differentiates `.5mean` squared error for all three branches on at most4096rows. Stable sigmoid exponent arguments are nonpositive. `training_scales` computes training-only RMS using scale-normalized arithmetic; scales<=1e-12 abstain. `physical_parameters` folds normalized coordinates into G/sx,U/sx,sy*D and rejects overflow/underflow.

`fit` receives initial parameters, train/guard arrays and the complete native-int64(4000,256) schedule externally. It has no filesystem, random generator, target or teacher imports. The caller must independently enforce input/resource/source/transport/disk gates, create the exclusive attempt marker and persist source/initial/random-state/schedule evidence before calling it on actual data. The kernel makes private immutable copies of train/guard arrays and schedule; account for these copies in the future exact memory inventory. It retains only17parameter/moment checkpoints and exposes one immutable parameter step event per update. An observer must stream step events rather than retain all4000parameter objects.

Adam uses4000updates, moments.9/.999, epsilon1e-8 and cosine learning rate.01atindex0to.0001at3999. There is no clipping, weight decay, normalization, restart, early success or quality threshold. Each Step event contains the post-update parameters and pre-update sampled loss. Checkpoint events occur at0,256,...,3840,4000. Their train loss is half normalized MSE; guard_mse is the actual normalized MSE. The earliest finite minimum guard MSE is selected, including step0. This guard is consumed calibration, never an unseen-test/generalization claim.

Guard Frobenius relative error uses scaled sums of squares so tiny nonzero targets do not become an artificial zero denominator. It is `None` only when the target is genuinely all zero. MSE overflow or underflow terminates the case rather than presenting an exact zero residual. Gradient/Adam arithmetic uses ordinary FP64 gradual underflow, with overflow/nonfinite errors rejected; no arbitrary-precision/exact-arithmetic claim is made. A NumericalFailure carries the completed update count and last finite parameter/moment state, not a successful prefix result. Observer exceptions propagate unchanged. The future trace/controller must persist checkpoint intent before arrays, ordinary failure states where possible, and unknown hard-interruption tails; this pure kernel itself writes nothing.
