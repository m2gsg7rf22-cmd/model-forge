# Reconstruction and independent model building

This page describes the original NumPy byte-model builder. Version 0.2 separately supports complete local GPT-2/Llama weights through [the HF runtime](local-runtime.md), [full/LoRA training](training.md) and [MLX](mlx.md). Those paths have separate formats, device support and rights gates; the limitations below apply to this NumPy builder.

Engine D includes a real NumPy CPU runtime for the project's own `modelforge-tiny-causal-v1` architecture. This is an independent model: random seeded weights, a lossless UTF-8 byte tokenizer, learned embeddings and positions, one causal self-attention head, a residual tanh activation and a vocabulary output projection. It has no relationship to a proprietary model. Non-UTF-8 generated byte sequences display replacement characters; numerical comparisons use tokens or logits, not rendered text.

```python
from modelforge.builder import create_model, load_model, train_model, compare_models, quantize_model

create_model("example", d_model=32, context_length=64)
model = load_model("example")
print(model.generate("hello", max_new_tokens=16))
model.save("replica")
print(compare_models("example", "replica"))
print(train_model("example", "abc abc abc abc abc", steps=100))
quantize_model("example", "example-int8")
```

For a dedicated accessible-fixture reconstruction, call `reconstruct_model("example", "rebuilt")` from `modelforge.builder`. It validates the supported architecture and tokenizer, reconstructs float32 tensors in the independent runtime, preserves training/rights history, records source config and weights SHA-256 values, and returns a finite prompt parity report. A quantized source reconstructs its dequantized tensors; it cannot recover the original float32 weights lost during quantization.

The model writes genuine SafeTensors weights, configuration, byte tokenizer description, provenance, a model card and a standalone `runtime.py`. Copy that directory and install NumPy to run independently of ModelForge. No pickle or model-supplied Python executes when importing weights. Loading accepts only this explicitly identified architecture, validates tensor shapes and offsets, rejects nonfinite weights and checks bounded resource estimates before loading payloads.

New bundles record SHA-256 hashes for configuration, tokenizer, weights and runtime source in `provenance.json`; loading validates these hashes when present. These detect accidental corruption and establish an auditable source chain. They are not a cryptographic authenticity proof, because somebody editing a bundle can also edit its unsigned provenance. The loader hashes runtime source but never executes it. Legacy bundles without hashes remain loadable after structural validation.

Training and fine tuning optimize the output projection and bias with cross-entropy gradients; the attention backbone stays fixed. This is useful for experiments and runtime acceptance tests but is not full transformer pretraining. Only the first context window plus its target byte is used, with `corpus_truncated` reported for longer corpora. Training data must be provided with appropriate authorization. The application never automatically collects service responses for training. Steps, context, width and corpus size have hard bounds. Inference uses greedy decoding with a sliding context window and reset position indices.

INT8 export uses symmetric per-tensor quantization and records scale tensors. It is a lossy storage format. Loading dequantizes weights to float32 for CPU execution; it provides no integer compute speedup. Compare both exports to measure finite prompt errors. LoRA, QLoRA, GGUF/ONNX export, general Hugging Face architecture inference, CUDA and MLX execution are unsupported by this builder. Inspecting an arbitrary weight format elsewhere in the app does not make that format runnable here.

Exact reload means the same project-owned float32 tensors produce exactly matching logits in this runtime on the tested inputs and environment. `compare_models` explicitly scopes its result to finite test prompts; it cannot prove universal equivalence or parity across hardware/libraries. Given external authorized weights, reconstruction still requires a matching implemented architecture, tokenizer and numerical conventions. This release does not supply general external architecture reconstruction.

Preflight estimates include parameter and intermediate arrays, checks the selected memory budget, and checks export disk space. They bound this small runtime's planned allocations; they cannot reserve system memory or prevent concurrent processes from consuming resources. Defaults fit CPU machines without a GPU. For a model derived from external assets, preserve upstream licenses and distribution restrictions; a rights string is a provenance declaration, not independent proof of ownership.

For an attached HF model, use Service.reconstruct_local with explicit redistribution permission and a rights statement. It writes a separate hf-reconstruction bundle with prompt parity and provenance; HF LoRA may be merged through this path. Project export includes that authorized reconstruction, not the original attached directory or raw training tree. MLX adapter merge/export remains unsupported.
