# ביקורת מקור מלאה — variable-width gate development v1

המקור המלא מאושר לניסיון עתידי אחד דרך default CLI בלבד, לאחר הקפאה נקייה ומעבר כל שערי זמן הריצה. זו חתימת מקור ותוכנית משאבים, לא קבלת משאבים בפועל ולא טענת הצלחה מדעית. לא נטענו מערכי המקור הרשומים ולא נוצרו generators מהזרעים הרשומים בביקורת.

## ממצאים שנסגרו

V1: קבלות scope ו־transport נשמרות מיד לפני בדיקתן ולפני בדיקות מאוחרות. בקרת fake engine עצמאית מאשרת שקבלת TREE כושלת נשמרת ו־RNG לא מתחיל. בדיקת ההורה לשטח דיסק בלתי זמין שומרת גם את שתי הקבלות.

V2: מקרה completed מחייב complete=1/count=8/attempted=8 בכל אצווה. כיווני pre/post, אצוות refinement, mixtures, eigenpairs/indices/starts והפסדי merge נקשרים ל־aggregates ולמסלול הספירות. הפסדים שחושבו בחלוקות BLAS שונות מושווים בסבילות מפורשת. בקרות עצמאיות דוחות partial chunk, שינוי שורה, הפסד merge סותר, pretrace שונה ו־Boolean במקום מונה.

V3: בסיס ה־trace נקשר בדיוק ל־job.basis ששימש בפועל. RED עצמאי קיבל בסיס trace מאופס כ־completed; אותו פרוב על המקור המתוקן נדחה. שתי התוצאות שמורות.

## מקור, מידע ותקציב

נחתם בדיוק ה־set שדורש REQUIRED_REVIEW בתוספת הרישום המוקדם, ללא מסמכי מצב משתנים. הוא כולל14 dependencies, בדיקות, מסמכים וראיות lineage. קובץ JSON מפרט את כל החתימות ואת מספרן. ארבע חתימות public metadata תואמות לראיות המועתקות וה־audit הקודם; 31 מקורות ההורה נשארו זהים. adapter ו־kernel החתומים לא שונו.

המסלול משתמש רק בששת בסיסי stable-p17 שכבר נאטמו, עם r חיובי וזוגי ועד192 וב־n32. כל54 קלטי הציבור,24 ארכיוני האומד ו־12 בחירות המקור נבדקים לפני חילוץ basis[:r]. רק job אטום ובסיס בלתי ניתן לשינוי עוברים לאופטימייזר. כשקלט pinned אינו תקין או מדרגתו odd/full/null, ה־adapter עוצר לפני RNG; תוצאה זו אינה מתחזה לתוצאת חיפוש מדעית של מקרה.

חישוב מלאי עצמאי מ־shapes ליטרליים תאם כל5,988 השמות והצורות וכל20 משפחות transport. חסם trace הוא306,834,564 בתים, כולל manifest עד772,596. חסם archive מרבי3,124,232; preflight עד9,020,691. עם parent מתוכנן534,980,568 ועוד8MiB מתקבל859,224,431 — פחות מ־1GiB. נכללים overshoot עד607, cosines בגודל607x607, geometry residual עד192x528, כל האצוות והעתקי aggregate. תכנון זה אינו הוכחה שכל ששת jobs יסיימו תוך180 שניות.

## מסלול סיום ומשאבים

default CLI מפעיל outer monitor לכל הבקר וילדיו ב־180 שניות/512MiB/BLAS1/2KiB. אימות מקור/runtime/clean HEAD, preflight TREE ו־20 משפחות transport, דיסק פנוי2GiB ו־marker חדש בלעדי precede RNG רשום. אין retry, החלפת seed, חיתוך מספר מועמדים או עקיפת marker עם output חדש.

כשל מדעי של zero/overshoot/geometry/exhaustion נרשם ומאפשר המשך במסגרת התקציב. כשל תפעולי עוצר את הניסיון ומשאיר failed_or_partial/not_started. קבלות, traces ודוחות נבדקים לפני השלמה, וכשל outer או כתיבת receipt גובר על הצלחה פנימית. completed pipeline יכול לכלול אפס candidate_target; תרחיש זה עבר בבדיקת ההורה עם קלטים ליטרליים, streams11/12 וטעינת נתונים מדומה.

ההורה דיווח78 בדיקות ממוקדות שעברו ב־24.41 שניות, כולל26 fixtures לפרוטוקול, בדיקות mypy ו־Ruff. לא הרצתי אותן שוב. שני setup failures בבקרות שלי נשמרו: צורת607 מול count1 שהוגדרה בטעות, ושינוי API מקביל שהוסיף שדות חובה; שניהם נדחו כראוי ולא היו כשלי מקור או ניסיונות מחקר.

משאבי הניסיון בפועל טרם נמדדו. RSS מדוגם אינו חסם שיא רציף או הקצאת OS. hard kill עשוי לאבד עד8 פלטים שלא נשמרו; flush או כתיבת דוח עשויים להיכשל, והמצב נשאר unknown. יש לשמור terminal checkpoint ואז לבצע אודיט נפרד של תוצאות שמורות, בלי fitting או שאילתות נוספות.

הנתונים הם פיתוח ציבורי שנצרך; אין heldout או fresh validation. r/2, ספירת מועמדים והפסד נמוך אינם תעודת כיסוי או זיהוי gates, magnitudes, couplings, פונקציה או משקולות. אין טענת bit parity כללית, ואין לייחס הבדלי precision באופן סיבתי כשזרמי החיפוש עצמאיים. השער הפרטי סגור; משימות השחזור האוניברסלי וה־backbone נשארות פתוחות.
